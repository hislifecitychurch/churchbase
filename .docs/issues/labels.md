# Issue labels

Use GitHub’s native issue Type—Task, Bug, or Feature—to classify work. Use labels to make an issue’s area or concern easy to filter; add a label when it helps triage, even for a specific task. Prefer an existing label over creating a one-off label, and add new labels when a useful work area is not covered. Do not add a label that merely duplicates the native issue Type.

## Active labels

| Label            | Color     | Use                                                     |
| ---------------- | --------- | ------------------------------------------------------- |
| `area: branding` | `#C2E0C6` | Churchbase logos, favicons, manifests, and brand usage. |
| `area: ui`       | `#BFD4F2` | User-facing interface layout and interactions.          |
| `area: workflow` | `#D4C5F9` | Repository and engineering workflow conventions.        |

## Legacy labels

These `type:*` labels are legacy. Do not add them to new issues; remove existing assignments as issues are migrated to native types.

| Label               | Color     | Use                                                             |
| ------------------- | --------- | --------------------------------------------------------------- |
| `type: feature`     | `#1D76DB` | Adds a product capability or user-facing workflow.              |
| `type: bug`         | `#D73A4A` | Fixes incorrect or broken existing behavior.                    |
| `type: maintenance` | `#6F42C1` | Chores, refactors, documentation, build, or configuration work. |
