# Churchbase Auth

Email-or-username/password sign-in and sessions are configured with BetterAuth's username and admin plugins; `apps/identity` calls BetterAuth and returns to an allowlisted app origin. The App then loads its Churchbase user through `GET /api/v1/users/me`; API authorization remains server-side. The API CLI may provision a new identity through the service-token-protected `POST /internal/provision-user` route; this creates only a BetterAuth identity with its default Auth role, while the Go API separately grants Churchbase `global_roles=admin`. The route is unavailable when `AUTH_SERVICE_TOKEN` is unset. After enabling the plugins on an existing database, run `bun run --cwd apps/auth db:migrate` to add their schema fields. Public email sign-up remains disabled in staging and production. Email verification, password-reset delivery, and account invitations are not implemented.
